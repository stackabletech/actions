# mergebom

mergebom turns the CycloneDX SBOM that `syft scan` produces for a container image into the SBOMs
that the [publish-image] action attests to the image:

1. It merges components that syft reports more than once. Components from SBOMs embedded in the
   image (generated by the product builds) win over the ones syft found itself.
2. It completes the dependency graph, so every component is reachable from the image.
3. It removes syft's bookkeeping properties and sets the metadata of the image (purl, supplier,
   description, license).
4. It writes the result as CycloneDX (1.7 by default) and as SPDX 2.3.

The SPDX document is built directly from the merged SBOM instead of with `syft convert`, so third
party packages do not inherit the supplier of the image, and deprecated license IDs are
canonicalised.

```shell
mergebom \
  --input sbom_raw.json \
  --cyclonedx-output sbom.cdx.json \
  --spdx-output sbom.spdx.json \
  --image-purl 'pkg:oci/kafka@sha256%3A...?arch=amd64&repository_url=oci.stackable.tech%2Fsdp%2Fkafka' \
  --image-description 'Apache Kafka. This image is deployed by the Stackable Operator for Apache Kafka.' \
  --image-license Apache-2.0
```

See `mergebom --help` for all options.

## Releasing

Push a tag `mergebom-<version>` (e.g. `mergebom-0.2.0`), with the version matching
`tools/mergebom/Cargo.toml`. The release workflow builds the binaries for x86_64 and aarch64,
signs them with cosign and attaches them to a GitHub release. Then bump the default of the
`mergebom-version` input of the [publish-image] action.
